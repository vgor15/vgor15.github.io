The flag that never changed

An interrupt sets a flag. The main loop waits for it. Everything works, until you turn the optimiser up and the loop waits forever. This is the story of volatile, told with my own CAN dashboard code.

The pattern

On Node A, a Timer1 interrupt sets a flag and the main loop sends a CAN frame when it sees it. This is the real code:

/* Timer_Intr.c */
u32 timer1 = 0;

void timer1_Handler(void) __irq
{
    timer1 = 1;
    T1IR = 1;
    VICVectAddr = 0;
}

/* Main_A.c */
while (1) {
    result = adc_read(2);
    ...
    if (timer1 == 1) {
        timer1 = 0;
        can2_tx(v1);
    }
}

Notice that timer1 is a plain u32, not volatile. It worked on the board anyway. Why?

Why it got away with it

The compiler is allowed to keep a variable in a register as long as it can prove nothing else changes it. But the loop calls adc_read(), uart0_tx_string() and friends, all defined in other files. The compiler can't see inside them, so it has to assume any of them might write to a global like timer1. After every call it reloads the value from memory, and the ISR's write gets seen. Luck disguised as correctness.

Where it breaks

Write the same wait without any function calls and the excuse disappears:

while (timer1 == 0);      /* wait for the next tick */

Nothing in that loop can change timer1 as far as the compiler knows, because interrupts are invisible to it. With optimisation on, it may load the value once and spin forever on a stale register. The ISR fires, memory changes, and the loop never looks.

The fix is one word

volatile u32 timer1 = 0;

volatile tells the compiler that every read must actually go to memory, because something it can't see might change it. This is also why my switch loop, while(sw1 == 0);, was always safe: sw1 reads IOPIN0, and the LPC21xx header already declares every peripheral register as a volatile pointer to a fixed address.

What volatile doesn't do

  • It doesn't make things atomic. flag ^= 1 in main() is a read, modify and write. If the ISR writes in between, one update is lost. Let only one side write a flag, or briefly disable the interrupt around the update.
  • It isn't a lock. For anything bigger than one word, copy it out with interrupts disabled.

Rule I follow now: anything shared between an ISR and main() is volatile, and every shared variable has exactly one writer.
