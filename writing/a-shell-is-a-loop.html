A shell is just a loop

Every shell you have used is a loop: read a line, split it, run it, wait, repeat. Writing imperfect_cell in C made that loop concrete, and taught me more about processes than any diagram did.

The whole program

Strip away the colours and the Dragon Ball jokes and the heart of cell.c is six lines:

while ((line = cell_read_line())) {
    args = cell_split_line(line);
    if (args[0] && !strcmp(args[0], "cd"))
        Chdir(args[1]);
    cell_execute(args);
    free(line);
    free(args);
}

Read

getline() with a NULL buffer lets libc allocate a line of any length, which is one less fixed-size buffer to overflow. The prompt is only printed when stdin is a terminal (isatty). It shows the working directory from getcwd() and, when the last command failed, its exit status in red: 🦠[~/src][69]🦠 >.

Split

strtok() cuts the line on whitespace into an array of pointers that starts at BUFSIZ entries and doubles with realloc when it fills. The array ends in NULL, because that's exactly what execvp expects.

Built-ins first

Some commands must run inside the shell itself. The built-ins live in a table of names and function pointers, closed with a NULL sentinel so the lookup is a simple walk:

t_builtin g_builtin[] = {
    {.builtin_name = "echo", .foo = cell_echo},
    {.builtin_name = "env",  .foo = cell_env},
    {.builtin_name = "exit", .foo = cell_exit},
    {.builtin_name = NULL},
};

env just walks extern char **environ. cd is the classic case for a built-in: chdir() in a child process changes only the child's directory, which disappears a moment later.

Fork, exec, wait

Everything else is an external program. fork() returns twice: 0 in the child, the child's PID in the parent. The child replaces itself with the program through execvp(), which searches PATH. The parent blocks in wait() and keeps WEXITSTATUS for the next prompt.

if (Fork() == CELL_JR)          /* CELL_JR == 0: we are the child */
    Execvp(args[0], args);       /* only returns on failure        */
else
    Wait(&status);

Fail loudly, in one place

Every system call goes through a capitalised wrapper (Fork, Execvp, Wait, Malloc, Realloc, Getline, Getcwd, Chdir) that checks the return value and prints a coloured perror. The main code reads like the happy path, and nothing fails silently. When execvp can't find a program, the child prints 💥CELL_Jr failed💥 and exits with EX_UNAVAILABLE (69).

What I'd fix next

  • Make cd a real built-in. Today cd runs in the loop, then also falls through to cell_execute, which forks and tries to execvp("cd"). The directory does change, but the prompt turns red with status 69. Moving it into the table fixes both.
  • Pipes and redirection: pipe(), dup2() and one child per stage.
  • Signals. Ctrl-C should stop the child, not the shell.
