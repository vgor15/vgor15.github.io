Two ECUs, one bus

At Vector India, our team of three built a two-node CAN network on LPC2129 boards. Node A senses, Node B shows. This is how one frame gets from a potentiometer to an LCD.

Why a bus at all

A car is a crowd of ECUs that all need to talk. Run a wire from every sender to every receiver and the harness grows with every module you add. CAN replaces that with one two-wire differential pair, CANH and CANL. Every node hears every frame, and the identifier on each frame decides both what it means and who wins when two nodes talk at once.

Node A: read, pack, send

Node A reads a speed potentiometer on AIN2 and an MCP9700 temperature sensor on AIN1 with the LPC2129's 10-bit ADC, and watches three switches on P0.14–P0.16. Every frame uses the same 11-bit identifier:

v1.id  = 0x500;   /* 11-bit identifier */
v1.rtr = 0;       /* data frame, not a remote request */
v1.dlc = 8;

result      = adc_read(2);   /* speed pot   */
temperature = adc_read(1);   /* MCP9700     */

if (timer1 == 1) {           /* set by the Timer1 interrupt */
    timer1   = 0;
    v1.byteA = result;
    v1.byteB = temperature;
    can2_tx(v1);
}

A Timer1 interrupt paces the telemetry, so the main loop never sleeps. Switch presses don't wait for the timer: each press toggles a flag and immediately sends an event code in byteA (0x05/0x06 headlight, 0x07/0x08 left, 0x09/0x10 right).

On the wire

byteA goes into the controller's C2TDA register (data bytes 1–4) and byteB into C2TDB (bytes 5–8). The on-chip CAN controller does the rest: start-of-frame, CRC-15, bit stuffing after five identical bits, the ACK slot, end-of-frame. A typical telemetry frame comes out at around 120 bits on the wire, about a dozen of them stuff bits.

Node B: interrupt, decode, draw

Node B doesn't poll. CAN2 receive is wired to VIC channel 27, and the handler copies the frame out and frees the receive buffer:

void CAN2_Rx_Handler(void) __irq
{
    v1.id  = C2RID;
    v1.dlc = ((C2RFS >> 16) & 0xF);   /* DLC lives in bits 19:16 */
    v1.rtr = ((C2RFS >> 30) & 1);     /* RTR is bit 30           */
    if (v1.rtr == 0) {
        v1.byteA = C2RDA;
        v1.byteB = C2RDB;
    }
    C2CMR = (1 << 2);                   /* release receive buffer  */
    VICVectAddr = 0;
}

The main loop turns raw ADC counts back into units. Speed is scaled to 0–280 km/h with 280 × ADC / 1023. The MCP9700 outputs 500 mV at 0 °C plus 10 mV per degree, so temperature is (ADC × 3.3 / 1023 − 0.5) / 0.01.

Eight glyphs of CGRAM

The 16×2 LCD is an HD44780 driven in 4-bit mode. It has room for eight custom 5×8 characters, written to CGRAM starting at address 0x40: left and right arrows, headlight beams, four battery levels and a °C sign. The indicators blink because a second timer interrupt toggles a flag that decides whether to draw the arrow or a blank.

What I'd change next

  • Give events their own identifier. Telemetry and switch codes share ID 0x500, and Node B checks only the low byte of byteA. A speed reading of 263 is 0x107, whose low byte is 0x07, which is "left indicator on". A separate ID removes the ambiguity and lets CAN arbitration put events ahead of telemetry.
  • Stop busy-waiting on switches. while(sw1==0); freezes the loop while a button is held. An external interrupt per switch fixes that.
  • Handle errors, add nodes. Watch the error counters, retransmit, and grow past two ECUs.
